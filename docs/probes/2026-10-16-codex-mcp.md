## Findings

1. **Registration.** A server in `$CODEX_HOME/config.toml` (`[mcp_servers.<name>]`) or on the command line alone
   (`-c 'mcp_servers.aos.command="/usr/local/bin/aos-agent"' -c 'mcp_servers.aos.args=["mcp"]'`) starts before the
   first model request, and its tools are offered as one Responses `namespace` tool, `mcp__<server>`, holding the
   server's own tool names: `mcp__aos` with `aos_ask`, `aos_reply`, `aos_inbox`, `aos_wait`, `aos_declare`,
   `aos_propose`. No allowlist is involved (unlike omp). Codex passes no parent environment variable to the server.
2. **The call.** A function call with `namespace: "mcp__stub"` and `name: "stub_ping"` ran under
   `approval_policy="never"` without an approval step and returned the result; the JSON stream reports it as an
   `mcp_tool_call` item (the runner's parser ignores it and keeps the final `agent_message`). A flat
   `mcp__stub__stub_ping` is refused (`unsupported call`).
3. **The repository's MCP files.** A `.codex/config.toml` in the working directory starts its servers beside ours and
   offers their tools, with the project marked `untrusted` or `trusted` alike; `.mcp.json` and `.claude/mcp.json` start
   nothing. A repository server named like one in `$CODEX_HOME/config.toml` replaces it.
4. **Command line against the repository.** `-c` keys outrank the repository's for the same keys (command, args, a
   named `env` key), but the repository's other keys merge in: its `[mcp_servers.aos.env]` reached our `aos` server
   (`mark=repo-env`) whether `-c` set `command` and `args`, `env={}`, or the whole table inline. A
   `PYTHONPATH` set there made a plain `python3` server import the repository's `json.py`; `python3 -I` did not. A
   `-c mcp_servers.other.enabled=false` for the repository's other server fails the start ("invalid transport"), and
   no flag skips project config (`--ignore-user-config` covers `$CODEX_HOME/config.toml` only).
5. **Call timeout.** A 130 s call completed with the default limit and with `tool_timeout_sec=1000`; one `aos_wait`
   call lasts up to 900 s, beyond what was measured, so the runner sets the limit.
